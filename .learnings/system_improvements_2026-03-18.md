# CogniMate 智伴 - 系统完善记录

## 一、发现的问题

### 1. 消息发送可靠性问题（核心问题）
**现象：**
- 3月17-18日，多次出现提醒延迟2-3分钟送达
- 部分提醒完全丢失（用户未收到）
- API 限流导致消息发送失败

**根本原因：**
```
Cron 任务 → AI处理(agentTurn) → 遇到429限流 → 重试 → 延迟/失败
```

**影响：**
- 用户无法在正确时间点收到提醒
- 补水提醒错过最佳时间
- 运动提醒延迟影响计划执行

### 2. 缺乏失败重试机制
**现象：**
- 消息发送失败后，没有自动重试
- 失败后用户无感知
- 没有失败告警

### 3. 提示词不够精确
**现象：**
- AI 在处理 cron 任务时，有时无法正确调用 message 工具
- 任务指令过于复杂，AI理解不一致
- 缺乏标准化的失败处理流程

## 二、完善方案

### 方案1：双重保障机制（已实施）

**架构：**
```
Cron 任务
    ↓
┌─────────────────────────────────────┐
│ 第一层：AI 处理 (agentTurn)          │
│   - 尝试使用 message 工具发送        │
│   - 如果成功，完成                   │
│   - 如果失败（429限流），进入第二层  │
└─────────────────────────────────────┘
                    ↓ 失败
┌─────────────────────────────────────┐
│ 第二层：SystemEvent 直接投递         │
│   - 绕过 AI 处理                     │
│   - 直接投递到 main session          │
│   - 作为备用方案                     │
└─────────────────────────────────────┘
```

**状态：** 已配置，待明天验证

### 方案2：失败重试机制（待实施）

**设计：**
- 第一次失败 → 等待30秒重试
- 第二次失败 → 等待60秒重试
- 第三次失败 → 放弃并记录错误
- 连续3次失败 → 发送告警给用户

### 方案3：提示词优化（已实施）

**优化内容：**
1. 明确指令："使用 message 工具发送飞书消息给用户..."
2. 指定目标：明确 user_id
3. 简化流程：减少 AI 决策环节

## 六、学习记录

### 学到的经验
1. **可靠性 > 智能** - 对于提醒功能，准时送达比智能处理更重要
2. **多层保障** - 单一方案容易失败，需要备用方案
3. **明确指令** - AI 需要非常明确的指令才能正确执行
4. **监控告警** - 必须有机制知道什么时候失败了

### 避免的错误
1. 不要完全依赖 AI 处理关键任务
2. 不要假设 API 总是可用
3. 不要忽视失败重试机制
4. 不要在没有验证的情况下大规模部署
