# 学习记录 - API 限流处理机制

## 问题
当 Kimi API 遇到 429 限流错误时，当前系统会直接失败，没有重试机制，导致用户收不到提醒。

## 用户的反馈
> "如果遇到限流的问题，你应该有重试机制，而不应该是直接不动"

## 当前的问题
1. **没有重试**：遇到 429 错误后直接失败
2. **没有告警**：用户不知道发生了什么
3. **没有降级方案**：无法绕过限流完成核心功能

## 改进方案

### 短期方案（已实现）
- ✅ 将提醒任务从 `agentTurn` 改为 `systemEvent` 直接投递
- ✅ 绕过 AI 处理，避免 API 限流问题

### 长期方案（待实现）
1. **消息队列 + 重试机制**
   ```
   Cron 任务 → 消息队列 → 尝试发送
                    ↓
              失败 → 延迟重试（指数退避）
                    ↓
              重试3次后仍失败 → 记录错误 + 人工介入
   ```

2. **多级降级方案**
   - 第一级：AI 处理 + 发送（正常情况）
   - 第二级：直接发送（AI 限流时）
   - 第三级：本地服务器直接调用飞书 API（OpenClaw 故障时）

3. **失败通知机制**
   - 任务失败后立即通知用户
   - 提供手动补发选项

4. **监控告警**
   - 连续多次失败时发送告警
   - 记录失败率统计
